# D3 review findings to fix before the PR (web, 9 Nov 2026)

The build is on this branch. Two independent reviews found these. Fix them, then run tsc, vitest, `MESH_LOCAL_DB=1 npx next build`, and take screenshots at 390 and 1440 px (fresh, and answered as sister, family, Kulliyah).

## Correctness review

1. **The guide grid changes height once a saved profile loads, so everything below it moves.** `src/features/home/HomeGuides.tsx:263-276`
   - Cards use `min-h-36 md:min-h-40` and grow with the title. When the client swaps in different guides, the row heights change.
   - Measured grid height, no profile against a profile:

     | Width | No profile | With a profile |
     |---|---|---|
     | 390 | 905 px | 740 to 863 px |
     | 768 | 824 px | 750 to 800 px |
     | 1440 | 417 px | 367 to 417 px |

   - On reload the browser puts the reader back at the same scroll position. Playwright then recorded a layout shift of 0.066 at 1440 from the guide cards. The updates and help sections below the grid also jump.
   - Fix: give each card a fixed height and clamp the title, for example `h-40 md:h-44 lg:h-48` with `line-clamp-3` on the title span. Size it for the longest live title at each breakpoint. The grid height then depends only on the card count, which never changes.
   - Add a Playwright or unit check that the grid height is the same with and without a profile.

2. **`HomePage.tsx` re-exports a client-module value from a server component.** `src/features/home/HomePage.tsx:15,20` (`export { STAGE_ICON };`)
   - `HomeGuides.tsx` is `"use client"`, so on the server `STAGE_ICON` is only a client reference, not the real icon map.
   - Nothing imports it from `HomePage` today. Any future server code that does `STAGE_ICON[g.stage]` through this export would throw ("cannot dot into a client module").
   - Fix: delete the re-export and its import. If a shared map is needed, move `STAGE_ICON` into a plain module such as `src/features/home/stageIcons.ts` with no `"use client"`, and import that from both files.

3. **The /start family view is never undone.** `src/features/home/WhoChooser.tsx:113-116`
   - `finish` sets the /start view to family whenever the household is family.
   - If the reader later changes to Single or presses Clear, /start stays filtered to family steps.
   - It also overwrites a "student" view the reader picked on /start themselves.
   - Fix: when the saved profile goes from family to single, or is cleared, call `updateStart((s) => (s.who === "family" ? { ...s, who: "all" } : s))`. Optionally only set family when `s.who === "all"`, so an explicit choice on /start is kept.

4. **(Low) The home page now loads all of the /start content on the phone.** `src/features/home/who.ts:1`, `src/features/home/WhoChooser.tsx:6`
   - `who.ts` imports `START_STAGES` and `WhoChooser` imports `start/store` (which imports `START_STEPS`). Together they pull all of `src/content/start.ts` (11.8 KB of source) into the home page's client bundle, for one stage title and blurb.
   - Fix: keep a small id-to-title/blurb map for the five places in `who.ts`, or have the server pass the stage data in. `updateStart` is only needed when the household is family, so the store can be loaded only at that moment with `await import("@/features/start/store")`.

Everything else checked out:
- No hydration warnings.
- With no profile, the eight guides are the same as today.
- Bad JSON, an old version and blocked storage all behave correctly; skip, change and clear work.
- The chooser box keeps the same height in every state at 390, 768, 1024, 1280 and 1440 (226, 182, 138, 138 and 138 px).
- Every button is at least 40 px tall, the focus ring shows, and focus moves to the next question and back to "Change".
- Dark mode works through `data-theme`, and nothing scrolls sideways at 390.
- `tsc` and `tests/who-are-you.test.ts` (27 tests) pass.
- No files outside the allowed set were touched.

The test server on port 3311 is stopped.

## Product review

1. **Answering "with family" switches /start into the Families view, which hides 10 student steps.** Families mode hides every step marked `for: "student"` in `src/content/start.ts`. For a Kulliyah student with family, the link goes to "The first week: The University, your address and your bank". With Families on, 4 of that stage's 7 steps are hidden (student card, University accounts, timetable, meals). The change also overwrites a view the reader picked on /start themselves, and choosing Single or Clear later does not undo it. Fix in `WhoChooser.finish`:
   - Set `who: "family"` only when the place is `visitor`, and only while `s.who === "all"`.
   - For a Ma'had, Kulliyah or postgraduate student with family, leave the view on Everyone.
   - Change the eyebrow from "Your family's next steps" to "Your next steps" whenever the reader is a student.

2. **Sisters are shown Islamic University campus guides.** The University's campus admits brothers; the sisters' guide lists the women's marakiz and the Masjid an-Nabawi Ma'had and Kulliyah instead. Now:
   - "Sister, single, Ma'had" or "Kulliyah" gets `university-housing-and-student-services` (University halls) and `campus-life-islamic-university`.
   - "Sister, applicant" gets `applying-to-the-islamic-university` first, with `women-at-masjid-an-nabawi` (a guide to the masjid) above `what-to-bring`.
   
   Fix in `WHO_RULES`:
   - For sisters at applicant, Ma'had or Kulliyah, give `sisters-studying-in-madinah` the top weight (at least 3).
   - Limit the single plus Ma'had or Kulliyah housing rules to brothers.
   - For sisters, lower the University-only guides (`campus-life-islamic-university`, `university-housing-and-student-services`, `registering-your-courses`, `applying-to-the-islamic-university`).
   - Add tests for "sister, applicant" and "sister, single, Kulliyah".

3. **Visitors get guides for people who live here.**
   - "Family, visiting" gets `finding-an-apartment` (6th) and `kindergartens-and-schools` (8th).
   - "Sister, visiting" gets `sisters-studying-in-madinah`, although the visitor hint says "not studying".
   
   Fix: let the family rule skip visitors (keep the visa guide through the family plus visitor rule). Let the sisters rule use only `women-at-masjid-an-nabawi` for visitors. Add a test that no visitor profile gets apartment, schools, baby or the sisters' study guide.

4. **The Ma'had and Kulliyah hints are hidden on phones.** The step 3 hints ("The Arabic institute", "A bachelor's degree", "Not in Madinah yet", "Here on a visit, not studying") are `sr-only` below `lg`. At 390 px a parent sees only "Applying, Ma'had, Kulliyah, Postgraduate, Visiting", and Ma'had and Kulliyah mean nothing to a newcomer. Show the hint as a second line at every width, using the space already reserved for the chooser (the box is 226 px at 390 and has empty space under step 1).

5. **"Saved on this phone only." is wrong on a laptop.** That line shows only at `md` and up, so it appears almost only on laptops and desktops. Use "Saved on this device only." in both places in `WhoChooser.tsx`.

6. **The third question is vague.** "Which fits you best?" says nothing about what is being asked. Use plain wording such as "Where are you now?" or "What brings you to Madinah?". With family, a wife or a parent may answer for the student, so the md+ helper line could say "Choose for the student in your family." Optional, but it removes a real point of doubt.

7. **Kulliyah and postgraduate newcomers skip arrival.** Both are sent to `/start#first-week`, but many Kulliyah and postgraduate students arrive from abroad. `new-student-steps` and `sim-internet-bank` are missing from the Kulliyah list, and the postgraduate list has the low-value `university-email-and-microsoft-365`, so a single postgraduate's top 8 falls back to `etimad-account` and `other-universities-in-madinah`. Fix:
   - Point postgraduate (and arguably Kulliyah) to `#arrival`, as the spec allows.
   - Add `new-student-steps` to the Kulliyah and postgraduate lists.
   - Swap the Microsoft 365 guide for `finding-an-apartment` or `living-on-a-visitor-id`.

8. **The section below the guide grid moves when the order changes.** Reordering keeps 8 cards but changes the row heights. At 1440 px the rows were about 200 px with 3-line titles and about 175 px after reordering. Give the title `line-clamp-3` and a fixed card height (`min-h-` set to the 3-line height) so the grid's height does not depend on which guides are shown.

9. **Keyboard users must go backwards to reach Skip.** After each answer, focus moves to the question heading. Skip, Clear and Cancel come before the heading in DOM order, so Tab goes straight to the options and then to the guide cards. Put the Skip or Cancel buttons after the option group in DOM order (they can stay at the top visually), or say "Skip" in the live region.

10. **Optional: first-time visitors see a brief flash.** The server renders the "Guides for everyone / Choose" view, which turns into question 1 right after load. The space is reserved and tested, so nothing moves, but the swap is visible. Only worth changing if the owner prefers to show question 1 by default.
