## Found on the way (not fixed here)
- **The webpack build rejects three route files.** `next build --webpack` fails its type check because `src/app/api/v1/assistant/route.ts` (`ASK_LIMITS`, aiakhee), `src/app/api/v1/track/route.ts` (`TRACK_LIMIT`, web) and `src/app/api/v1/push/subscribe/route.ts` (`SUBSCRIBE_LIMIT`) export constants that are not route fields. Turbopack, which Vercel uses, accepts them, and they have deployed before, so production is not blocked. Moving each constant into a sibling module (for example `limits.ts`) keeps the route files to the allowed exports and protects against a future Next upgrade.
- **The worktree junction goes stale.** A worktree whose `node_modules` is a junction to the main checkout fails on any package that `main` added later (`@tiptap/extension-table` today). Use `npm ci` in the worktree when `package.json` changed.

## After the deploy (live crawl of medinahub.org at `7f84882`, same tools)
The push of `7f84882` got past Vercel's limit, so production now runs all 12 held-back merges plus these fixes. The live crawl (summary in `2026-11-09-live-7f84882-crawl-summary.md`) matches the local one: no broken pages, no sideways scroll, no doubt wording, breadcrumbs at 40 px. It found two problems that only show in production:

1. **Hydration error on the home page (React #418), fixed in the next commit.** The "Last checked N min ago" line (`src/features/home/TimeAgo.tsx`, the desktop agent's own code) read the clock during the browser's first render. Once the cached page was a minute or more old, the browser's minute count differed from the server's. Reproduced locally by serving the home page from a cache more than two minutes old, and gone after the fix (the one text node may differ, and the mount effect corrects it at once; `display: contents` keeps the line's layout identical).
2. **Two Arabic font preloads 404 on every Arabic page (about 250 pages), handed to web.** `src/app/(ar)/ar/arabic-fonts.ts` hard-codes the file names of the local build (`b4416af7d770c10a-s.1zf0xf1cyi65q.woff2`, `ae8a6189deba2b59-s.29a202atpp3ye.woff2`). Vercel's build names them `b4416af7d770c10a-s.18tjh3qqaxhod.woff2` and `ae8a6189deba2b59-s.3hmcy8y9xj1sc.woff2`, and serves CSS from `/_next/static/immutable/`. The fonts still load from the stylesheet, so pages look right, but each Arabic page makes two failing requests and logs a console error. A hard-coded name cannot match both builds. One fix is a second `next/font` declaration with `preload: true` imported only by the Arabic layout; the other is to drop the manual preload.
