## Checked and found fine
- Every server action goes through `run(perm)` and `requireAdmin`, and every service checks `assertCan` again; every admin page passes the right permission (analytics is owner-only, as decided). Server actions are POST with Next's Origin check; Better Auth checks the origin against its base URL. No `allowedOrigins` widening.
- Cron routes use the constant-time `cronAuthorized`; an unset secret never authorises.
- No secrets in the tree (only `.env.example` is tracked); no open redirects (no redirect parameter anywhere); all `dangerouslySetInnerHTML` uses are sanitized or escaped (JSON-LD escapes `<`, FAQ and guide HTML go through `sanitizeArticleHtml`, the assistant renderer escapes first).
- The `adhan` and `minisearch` libraries are not in any public client chunk (row 28 holds). Public first-load JS is 134 to 181 KB gzip; the tiptap editor (125 KB gzip, 285 KB gzip for those pages in total) loads only on the four admin editor pages; `qrcode` only on 2FA setup.
- Riyadh dates: server code uses `riyadhDateIso` and noon-UTC helpers; the admin day grouping, key dates and countdowns all use Asia/Riyadh. Only finding 32 slips.
- Shared components: skip link, single visible `nav` landmark, `aria-current` on nav and breadcrumbs, icon-only buttons have labels, the YouTube embed is a labelled button. Token contrast passes AA in light and dark except findings 11 to 13.
