1. WHAT MESH IS
======================================================================
medinahub.org is MESH, the Medina English Student Hub: run by students, for English-speaking
students and families in Madinah. Maintainer and owner: Muhaymin (GitHub iumuhaymin).
It offers:
- Live duroos schedules of the mashayikh at Masjid an-Nabawi, Quba and city masjids, kept current by a
  Telegram watcher (AI reads channel posts, publishes clear changes or queues them for admins).
- Dars pages, shaykh pages (20 of 31 shuyukh have verified photos; the rest show a calligraphic name
  badge), a weekly schedule with filters, a Sisters section, a Live page.
- Study in Madinah: the University, Arabic institutes, marakiz, sisters' programmes (impartial,
  alphabetical, fees and dates, "last checked" dates).
- Guides (arrival, iqama and Visitor ID, banking, SIM, housing, transport, healthcare, family, university
  rules, calendar), FAQs ("Ask"), student discounts, key dates with countdowns and a subscribable
  calendar feed (/api/v1/calendar/dates.ics).
- A course-book library: 1,682 files for every college and the Ma'had, by level and subject, read
  inside MESH through an embedded Google Drive reader, with search (/library, /library/<college>,
  /library/read/<id>, /library/search).
- Arabic version under /ar (duroos, programmes, guides, ask, library, discounts, more) with a header
  language switch that remembers the choice.
- An admin panel (/admin): invite-only, Face ID passkey second factor, "Needs you" home block, watcher
  inbox, content editing, search, activity log with undo, confirm sheet and undo toast, a "Questions for
  you" page where admins answer open questions.
- It promotes the MESH WhatsApp group.

2. THE OWNER'S RULES (follow all of them, always)
======================================================================
Copy and tone
- No em dashes or en dashes anywhere (a test in tests/copy.test.ts scans visible text).
- No AI-sounding copy. Plain, warm, specific, professional English. Not casual.
- Speak with authority. Public text NEVER mentions a source, channel, post, poster or other website,
  and never shows doubt ("reportedly", "not stated", "unconfirmed", "inferred", "as last reported").
  The owner wants visitors to feel MESH has the information, not to leave for other sources.
- Unsure means ask, never guess: leave the fact out and add a question for admins
  (scripts/open-questions.json, then npm run questions:add -- scripts/open-questions.json; it appears in
  Admin > More > Questions for you). Answers are only saved; run npm run questions:pull to write them to
  docs/ADMIN-ANSWERS.md, then interpret them and publish properly.
- Research notes and admin-only notes never appear publicly.
- Plain words over jargon ("Course books" not "muqarrarat"; keep the Arabic beside it where students
  search for it).
- Rewrite everything in MESH's own words. Never copy sites or PDFs.

Impartiality and promotion
- Impartial: never recommend, feature or rank one markaz, institute, business or doctor. List
  alphabetically. Say MESH is student-run and independent. MESH must never be held accountable:
  protective lines like "confirm fees with the institute before you pay" are fine.
- No adverts or short-term promotions. No one-off trips, tours, sales or events that read like adverts,
  even when the owner pastes a poster. Only long-term real services and neutral facts.
- Never advertise or name other sites' businesses or groups as promotion.

Design
- Light theme by default; dark ("Madinah Night") only via the theme button.
- Brand: deep green #145c3e, gold #e2b23a, heavy white wordmark, diamond lattice pattern.
- Mobile first, but desktop must use the space with NO big empty areas.
- Check every visual change at 2000, 1440, 1024, 390 and 360 px.
- No filler features. Every element must help someone do something. (The owner rejected a decorative
  "Get ready" checklist as useless.) The owner wants the site rich, beautiful and interactive, with
  useful links everywhere they belong.
- English and Arabic both work (RTL).

Facts and freshness
- Facts that change (fees, dates) show when they were last checked.
- Temporary information expires: discounts, offers, trips, registration windows and one-off events
  must be removed or updated as soon as their period ends. Log every temporary item in
  docs/EXPIRING.md and sweep that table at the start of every session and before every deploy.
- Iqama and Visitor ID: most current students hold an iqama; the newest intake arrives on a digital
  Visitor ID with an electronic study visa (no iqama, no exit and re-entry). Banking, SIM, licence and
  visa guides cover both paths side by side.
- Shaykh photos: only verified photos (two independent sources, a wrong face is worse than none). The
  owner wants every shaykh pictured where a verified photo exists. ShaykhBadge is the fallback.

Names and contacts
- The owner's name (Muhaymin) is fine in code and docs. It never appears on the public site.
- Public help text: "please message Admin on WhatsApp at +1 234 567 9076" (a real number, fixed in code
  as HELP_CONTACT_DEFAULT in src/server/settings.ts, deliberately not editable in the admin).
- The owner has a private spare number; never put it anywhere public or in docs.

Engineering
- Never push to main without npx tsc --noEmit and npx vitest run passing.
- Never print or commit secrets.
- Free notifications only. Keep the site API-first (/api/v1) for a later native app.
- Previews never touch the live database.

How the owner likes to work
- Autonomous: the owner gave standing permission to continue work without asking, including restarting
  after usage resets. Ask only for genuine decisions (money, deleting data, outward actions).
- Conserve tokens. Prefer targeted greps and small reads over reading big files. Use cheaper models for
  side work where quality allows. Watch usage (get_usage) and stop at a safe point near the limit,
  commit, push and update docs/HANDOFF.md.
- Never delete the owner's data or chats; prefer unpublishing (status draft) to deleting.
- Short, clear replies. The owner often reads on a phone.

9. GOTCHAS
======================================================================
- tsconfig.tsbuildinfo is ignored; do not commit it.
- Dev server: restart it and delete .next/dev if pages look stale; never run next build while dev runs.
- Git Bash: apostrophes in node -e break; write scripts to files. Use MSYS_NO_PATHCONV=1.
- Escaping: when generating TS through scripts, regex escapes like \p{L} get mangled; prefer the Edit
  tool for regexes.
- React: store a function in state with setX(() => fn).
- Duroos pages never reach networkidle in headless Edge; wait for "load".
- Full-page screenshots need reducedMotion "reduce" or scroll-reveal cards stay hidden.
- The CSP (src/server/security.ts) must list any new iframe origin (Drive and YouTube are allowed).
- Shaykh Mis'ad's slug stays masad-ibn-musaid-al-husaini so links do not break.
- Scheduled restarts (CronCreate) live only in the session that made them; switching accounts drops them.
